 ## Goal
Update `sdk/python/test_sdk.py` to add a LongMemEval search-benchmark section that queries the pre-seeded Neo4j data (`user_id="longmemeval-user"`), measures client-side latency for both standard semantic search and enhanced (spreading activation) search, and prints aggregate analytics.

---

## Constraints
- All existing CRUD / integration tests remain unchanged and continue to run.
- No new third-party dependencies (only stdlib: `time`, `statistics`, `random`, `os`).
- Gracefully skip if the oracle JSON is unreachable or the seeded DB data is absent.
- Sample 50 questions with a fixed random seed for reproducibility.

---

## Chunks

### Chunk 1: LongMemEval Search Benchmark Section
- **Scope**: `sdk/python/test_sdk.py`
- **Depends On**: None
- **Accept When**:
  1. The script resolves `data/longmemeval_oracle.json` (tries multiple relative paths) and loads a random sample of 50 questions.
  2. For each sampled question it calls `client.memories_search(query, limit=10, user_id="longmemeval-user")` and `client.search_enhanced(query, mode=SearchMode.SPREADING, limit=10)` (or `SearchMode.VECTOR`), recording `time.perf_counter()` latency in milliseconds.
  3. After the batch it prints aggregate statistics per mode: count, min, max, mean, median, p95, p99.
  4. Running `python test_sdk.py` still passes all existing checks and the new benchmark section runs without errors.

---

## Verification Strategy
```bash
cd sdk/python && pip install -e .
python test_sdk.py --base-url http://localhost:8080
```
Confirm the new section heading appears and latency analytics are printed.
