## 2024-06-25 - SQL Injection Vulnerability in pgvector table names
**Vulnerability:** The pgvector client uses `fmt.Sprintf` with unvalidated `cfg.Table` configuration values to construct SQL queries (`CREATE TABLE`, `INSERT`, `SELECT`, `UPDATE`, `DELETE`). Table names cannot be natively parameterized in PostgreSQL queries, allowing an attacker to inject arbitrary SQL statements if the configuration value (which can come from an environment variable `PGVECTOR_TABLE`) is manipulated or influenced by untrusted input.
**Learning:** Even internal configuration values used directly in SQL structure queries (like table names) must be strictly validated because parameterization is not supported for them. The architecture assumed environment variables were fully trusted, which is a significant security gap.
**Prevention:** Always validate SQL identifiers (like table names, column names) against a strict allowlist or regular expression (e.g., `^[a-zA-Z0-9_.]+$`) before using them in string formatting functions like `fmt.Sprintf` to construct SQL queries.
