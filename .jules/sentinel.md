## 2024-05-18 - Insecure Random Number Generation Fallback
**Vulnerability:** Found multiple instances where `crypto/rand.Read` failures were handled insecurely. In some places (like `internal/sso/saml.go` and `internal/sso/ldap.go`), it fell back to using predictable timestamps (`time.Now().UnixNano()`). In others (like `internal/sso/oidc.go` and `internal/mcp/oauth/handler.go`), the error was completely ignored, resulting in tokens generated from empty byte slices (all zeros).
**Learning:** Cryptographic functions can fail, but falling back to weak randomness or ignoring the error completely defeats the purpose of using strong crypto random. This can lead to predictable session tokens, OAuth codes, and request IDs, enabling session hijacking or forgery.
**Prevention:** When generating secure tokens using `crypto/rand`, always handle `rand.Read` errors explicitly (e.g., by panicking or returning the error). Never ignore the error or fallback to predictable values like timestamps.
