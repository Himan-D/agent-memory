## 2024-06-27 - Insecure Token Generation Fallbacks
**Vulnerability:** Found insecure fallback mechanisms in token generation functions (e.g., `generateSessionToken` in `internal/sso/ldap.go`, `generateSamlSessionToken` and `generateSamlRequestID` in `internal/sso/saml.go`, and others) where a failure in `crypto/rand.Read` silently falls back to highly predictable values based on `time.Now().UnixNano()`.
**Learning:** Some token generation implementations attempt to handle `rand.Read` failures gracefully by returning a predictable fallback value. However, for security-critical tokens (session IDs, request IDs), returning a predictable value completely undermines the security of the system, making it vulnerable to token guessing attacks.
**Prevention:** Always handle `crypto/rand.Read` errors explicitly, either by returning the error to the caller or by panicking if it's considered a fatal system failure (as the system can't guarantee secure randomness). Never silently fallback to predictable non-cryptographic sources like system time.
