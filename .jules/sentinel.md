## 2025-02-28 - [CRITICAL] Prevent SQL Injection in Dynamic Identifiers
**Vulnerability:** A SQL injection vulnerability existed in the pgvector client where the `PGVECTOR_TABLE` configuration value was interpolated directly into SQL statements using `fmt.Sprintf` (e.g., `CREATE TABLE IF NOT EXISTS %s`, `SELECT ... FROM %s`) without any validation. Since PostgreSQL identifiers like table names cannot be parameterized with placeholders (e.g., `$1`), an attacker with control over the configuration could execute arbitrary SQL statements.
**Learning:** In Go backend code, when constructing SQL queries dynamically, SQL identifiers (table names, column names) cannot be safely parameterized. This represents a significant architecture-specific gap when relying on configuration values for table names that are later utilized in raw SQL execution.
**Prevention:** Always validate dynamic SQL identifiers with strict regex matching (e.g., `^[a-zA-Z0-9_]+$`) *before* using them in string interpolation functions like `fmt.Sprintf` to prevent SQL injection. This approach enforces strong allowlisting of acceptable characters.
