## 2026-06-30 - Insecure PRNG Fallback in SSO Tokens
**Vulnerability:** The SAML and LDAP SSO implementations were falling back to a highly predictable timestamp (`time.Now().UnixNano()`) if the cryptographically secure random number generator (`crypto/rand.Read`) failed. This could allow an attacker to predict session tokens and hijack authenticated sessions during periods of low entropy or if the PRNG is compromised.
**Learning:** Never ignore or "gracefully recover" from cryptographically secure PRNG failures by substituting insecure random values (like timestamps or math/rand). A failure in `crypto/rand` represents a catastrophic systemic failure where no secure random numbers can be generated.
**Prevention:** Always handle `crypto/rand.Read` errors explicitly. For session tokens or critical cryptographic materials, if `rand.Read` fails, the application should panic or explicitly return the error up the call stack to halt the operation, ensuring insecure values are never used.
