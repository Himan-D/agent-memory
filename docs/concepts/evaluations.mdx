# Evaluations

Hystersis includes a comprehensive evaluation system for benchmarking memory retrieval performance.

## Metrics

### Recall
Measures the fraction of relevant memories that were retrieved.

```json
{
  "score": 0.85,
  "relevant_retrieved": 17,
  "total_relevant": 20,
  "mrr": 0.78,
  "ndcg": 0.82
}
```

### Precision
Measures the fraction of retrieved memories that are relevant.

```json
{
  "score": 0.72,
  "retrieved_relevant": 18,
  "total_retrieved": 25,
  "ap": 0.68
}
```

### Faithfulness
Measures how well retrieved content matches the query intent.

```json
{
  "score": 0.91,
  "total_claims": 15,
  "accurate_claims": 14
}
```

### Latency
Tracks response time percentiles.

```json
{
  "avg_ms": 45.2,
  "p50_ms": 38.0,
  "p95_ms": 120.5,
  "p99_ms": 180.0,
  "total_calls": 1000
}
```

## Creating Test Sets

```go
testset := &evaluations.TestSet{
    ID:          "eval_001",
    Name:        "Product Questions",
    Description: "Benchmark for product-related queries",
    Queries: []evaluations.TestQuery{
        {
            ID:    "q1",
            Query: "What is the pricing for Pro plan?",
            Expected: []string{"mem_123", "mem_456"},
        },
    },
    GroundTruth: []evaluations.GroundTruth{
        {
            QueryID:   "q1",
            MemoryID:  "mem_123",
            IsRelevant: true,
        },
    },
}
```

## Running Evaluations

### Full Evaluation

```go
evaluator := evaluations.NewDefaultEvaluator(
    retriever, // func(ctx, query, limit) ([]RetrievedDoc, error)
    llmJudge,  // func(ctx, claim, context) (bool, error)
)

result, err := evaluator.Run(ctx, testset)
fmt.Printf("Overall Score: %.2f\n", result.OverallScore)
```

### Individual Metrics

```go
// Just recall
recall, _ := evaluator.RunRecall(ctx, testset)

// Just precision
precision, _ := evaluator.RunPrecision(ctx, testset)

// Just faithfulness
faith, _ := evaluator.RunFaithfulness(ctx, testset)
```

## Benchmark Suites

Run multiple test sets together:

```go
suite := &evaluations.BenchmarkSuite{
    Name:        "Full Benchmark",
    Description: "Comprehensive evaluation",
    TestSets:    []*evaluations.TestSet{testset1, testset2},
    Evaluator:   evaluator,
}

result, _ := suite.Run(ctx)
fmt.Printf("Benchmark Score: %.2f\n", result.OverallScore)
```

## Test Set Manager

Manage evaluation test sets:

```go
manager := evaluations.NewTestSetManager()

// Add test set
manager.Add(testset)

// Get test set
ts, _ := manager.Get("eval_001")

// List all
all := manager.List()

// Delete
manager.Delete("eval_001")
```

## Interpreting Results

| Score | Rating | Description |
|-------|--------|-------------|
| 0.90+ | Excellent | Production ready |
| 0.75-0.90 | Good | Minor improvements needed |
| 0.50-0.75 | Fair | Significant improvements needed |
| < 0.50 | Poor | Major rework recommended |

## Running benchmarks from the CLI

The `benchmark` command runs the bundled retrieval and ingestion suites against a live Hystersis backend (or an in-memory mock). Use it to validate retrieval quality after configuration changes, before a release, or to compare search modes on your own data.

### Quick start

```bash
# Run the retrieval suite on every dataset against a live backend
benchmark --suite retrieval --dataset all --mode hybrid

# Smoke test against the in-memory mock (no databases required)
benchmark --suite retrieval --dataset locomo --mock

# Cap the run to 50 questions and write a JSON report
benchmark --suite retrieval --dataset longmemeval --limit 50 --output report.json
```

### Flags

| Flag | Default | Description |
|------|---------|-------------|
| `--suite` | `retrieval` | Benchmark suite to run: `retrieval`, `ingestion`, or `all`. |
| `--dataset` | `all` | Dataset to evaluate: `locomo`, `longmemeval`, `beam_1m`, `beam_10m`, or `all`. |
| `--mode` | `hybrid` | Search mode passed to the live backend: `vector`, `hybrid`, or `spreading`. |
| `--parallel` | `1` | Number of concurrent in-flight requests. Defaults to `1` so a self-hosted LLM judge (Ollama, vLLM, etc.) is not overloaded — raise it when pointing at a managed API. |
| `--limit` | `0` | Cap on the number of questions evaluated per dataset. `0` runs every question. |
| `--mock` | `false` | Skip the live backend and run against an in-memory lexical mock. Useful for CI smoke tests. |
| `--output` | `""` | Optional path to write the full result as JSON. |

### Configuring the LLM judge

Retrieval suites score answers with an LLM judge. The benchmark CLI loads a `.env` file from the working directory on startup, then resolves judge credentials from environment variables. Set the evaluator vars to point the judge at any OpenAI-compatible, Anthropic, or Google endpoint:

| Variable | Description |
|----------|-------------|
| `EVALUATOR_API_KEY` | API key for the judge model. Falls back to `COMPRESSION_VERIFY_API_KEY`. |
| `EVALUATOR_BASE_URL` | Optional custom base URL (for example a self-hosted gateway). Falls back to `COMPRESSION_VERIFY_BASE_URL`. |
| `EVALUATOR_MODEL` | Judge model name. Falls back to `COMPRESSION_LLM_VERIFY_MODEL`, then to Google's `gemini-3.1-pro-preview`. |
| `COMPRESSION_LLM_VERIFY_PROVIDER` | Provider for the judge: `google`, `openai`, `anthropic`, `groq`, or `deepseek`. Defaults to `google`. |

If only an API key is supplied, the CLI defaults to Google `gemini-3.1-pro-preview`. When the evaluator variables are unset, scoring runs in heuristic mode and the result is marked as non-publishable.

Example `.env` for a self-hosted run with a Gemini judge:

```bash
EVALUATOR_API_KEY=AIza...your-gemini-key
EVALUATOR_MODEL=gemini-3.1-pro-preview
COMPRESSION_LLM_VERIFY_PROVIDER=google
```

Or to evaluate with a local OpenAI-compatible server:

```bash
EVALUATOR_API_KEY=sk-local
EVALUATOR_BASE_URL=http://localhost:11434/v1
EVALUATOR_MODEL=llama3.1:70b-instruct
COMPRESSION_LLM_VERIFY_PROVIDER=openai
```
